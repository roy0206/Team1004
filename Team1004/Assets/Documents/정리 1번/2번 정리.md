# 초지일관 연어 게임 — 최신 통합 기획서 / Claude 프로토타입 제작용

> 목적: 이 문서는 현재까지 확정된 게임 기획을 한 번에 정리한 최신 기준 문서다. Claude는 추가 질문 없이 이 문서를 기준으로 플레이 가능한 프로토타입을 제작한다.
>
> 우선순위: **기능의 수보다 게임 전체 흐름을 처음부터 엔딩까지 완성하는 것**을 최우선으로 한다. 미확정 세부 수치는 프로토타입용 임시값으로 적용하고, 나중에 쉽게 수정할 수 있도록 CONFIG에 분리한다.

---

# 1. 게임 핵심 정보

- 주제: **초지일관**
- 장르: **2D 사이드뷰 횡스크롤 회피 액션 게임**
- 플레이어 캐릭터: **성체 연어**
- 기본 진행 방향: **오른쪽**
- 기본 조작: **위 / 아래 이동 + 상단에서 위 입력 시 점프**
- 기본 레인 수: **3개**
- 핵심 플레이: 장애물을 피하고 보스 공격을 버티며, 처음 정한 목적지인 자신이 태어난 상류까지 돌아간다.
- 게임은 스토리와 엔딩이 존재하는 **완주형 게임**으로 제작한다.
- 상점, 코인, 강화, 스킬 트리, 공격 버튼 등 복잡한 시스템은 넣지 않는다.

---

# 2. 주제 ‘초지일관’의 해석

이 게임에서 초지일관은 단순히 한 방향으로 계속 이동하는 것을 의미하지 않는다.

게임에서 표현하려는 초지일관의 의미는 다음과 같다.

> **상황과 방법은 달라져도, 처음 품은 뜻은 끝까지 바꾸지 않는 것.**

주인공 연어는 게임 시작에서 하나의 목표를 정한다.

> **“무슨 일이 있어도, 내가 태어난 곳까지 돌아간다.”**

게임 도중 여러 위험과 방해 요소가 등장하지만 목적지는 바뀌지 않는다.

보스를 이기는 것 자체가 최종 목표도 아니다. 세 번째 보스를 통과한 뒤에도 마지막 일반 플레이 구간이 존재하며, 실제로 태어난 장소에 도착했을 때 게임이 끝난다.

---

# 3. 주인공 연어 캐릭터성

캐릭터 이름은 현재 필요하지 않으며 게임 안에서 별도 이름을 사용하지 않아도 된다.

주인공의 성격은 다음과 같다.

- 처음부터 모든 것을 두려워하지 않는 영웅형 캐릭터가 아니다.
- 위험하면 겁을 먹는다.
- 힘들면 투덜거린다.
- 가끔 포기하고 싶어 한다.
- 하지만 상당히 고집이 세다.
- 한번 스스로 정한 것은 쉽게 바꾸지 않는다.
- 흔들리지 않는 캐릭터가 아니라, **흔들려도 결국 처음의 뜻으로 돌아오는 캐릭터**다.

캐릭터 핵심 한 문장:

> **“겁도 많고 투덜거리지만, 한번 마음먹은 것은 끝까지 밀고 가는 고집쟁이 연어.”**

대표 대사:

> **“그래도 가야지.”**

이 대사는 중요한 순간에만 사용한다.

- 중간 컷신 1, 2, 3은 각각 **5문장 이내**로 제한한다.

# 5. 시작 스토리

목적:

- 연어가 왜 상류로 가는지 설명한다.
- 게임의 ‘처음의 뜻’을 명확히 만든다.

시작 스토리는 중간 컷신보다는 조금 길어도 되지만 짧고 명확하게 구성한다.

## 시작 스토리 대사/연출안

어린 연어가 자신이 태어난 상류의 자갈밭을 바라본다.

> “여기는 기억해 둬야겠다.”
>
> “나중에 다시 돌아오게.”

장면 전환.

시간이 흐르고 바다에서 성장한 성체 연어가 다시 자신의 강으로 돌아온다.

> “…여기다.”
>
> “무슨 일이 있어도…”
>
> “내가 태어난 곳까지 돌아간다.”
>
> “그래도 가야지.”

이후 즉시 게임 진행 1 시작.

권장 길이: 약 15~25초.

---

# 6. 기본 화면 구성

- 카메라: **사이드뷰**
- 화면비: 16:9
- 프로토타입 권장 해상도: 1280 × 720
- 연어는 화면 왼쪽 약 20~25% 지점에 위치한다.
- 배경과 장애물이 오른쪽에서 왼쪽으로 이동하면서 연어가 계속 오른쪽으로 전진하는 느낌을 만든다.
- 물속에는 총 3개의 수평 레인이 존재한다.

레인:

1. 상단 레인
2. 중단 레인
3. 하단 레인

프로토타입 임시 Y 좌표 예시:

- 상단: 250
- 중단: 360
- 하단: 470

플레이어 시작 위치:

- **중단 레인**

배경은 제작량을 줄이기 위해 물속 배경 1~2종 정도로 제한한다.

---

# 7. 기본 조작

## 이동

- ↑ 또는 W: 한 레인 위로 이동
- ↓ 또는 S: 한 레인 아래로 이동
- 좌우 이동 불가
- 한 번 입력할 때 정확히 한 레인만 이동
- 키를 계속 누르고 있어도 연속 이동하지 않음

예시:

- 하단 + ↑ → 중단
- 중단 + ↑ → 상단
- 상단 + ↑ → 점프
- 상단 + ↓ → 중단
- 중단 + ↓ → 하단
- 하단 + ↓ → 아무 일도 없음

---

# 8. 레인 이동 세부 규칙

- 레인 이동 시간: **약 0.2초**
- 순간이동처럼 보이지 않고 부드럽게 이동한다.
- 레인 이동 중에는 장애물과 충돌하지 않는다.
- 단, 이동이 완료되기 전 추가 입력은 모두 무시한다.
- 입력 예약 기능 없음.
- 이동 완료 순간부터 다시 충돌 판정 적용.
- 이동 중 반대 방향 입력도 무시.
- ↑와 ↓가 거의 동시에 눌린 경우 먼저 눌린 입력 적용.
- 시스템상 완전히 동시에 입력된 경우 둘 다 무시.

프로토타입 기본값:

```js
LANE_MOVE_DURATION = 0.2
```

---

# 9. 점프

상단 레인에서 ↑를 입력하면 연어가 물 밖으로 점프한다.

별도의 Space 키는 사용하지 않는다.

## 점프 규칙

- 점프 지속시간: 약 **0.8초**
- 점프 중에는 모든 물속 장애물과 충돌하지 않는다.
- 점프 중 ↑/↓ 입력은 무시한다.
- 점프 중 레인 변경 불가.
- 점프 종료 후 자동으로 상단 레인에 착수.
- 착수 완료 순간부터 다시 충돌 판정 적용.

프로토타입 기본값:

```js
JUMP_DURATION = 0.8
```

---

# 10. 점프 쿨타임

점프만 반복하는 플레이를 방지하기 위해 쿨타임을 사용한다.

- 점프 종료 후 물속에 착수한 순간부터 쿨타임 시작.
- 쿨타임: 약 **1.2초**
- 쿨타임 중 상단에서 ↑를 눌러도 점프하지 않는다.
- 쿨타임 종료 후 다시 점프 가능.

프로토타입 기본값:

```js
JUMP_COOLDOWN = 1.2
```

---

# 11. 점프 쿨타임 UI

화면 좌측 하단에 원형 UI를 배치한다.

## 점프 가능

- 아이콘 밝음
- 원형 게이지 100%

## 점프 사용 직후

- 아이콘 어두움
- 게이지 0%

## 쿨타임 진행

- 원형 게이지가 시계 방향으로 차오름

## 완료

- 게이지 100%
- 아이콘 다시 밝아짐

남은 시간을 숫자로 표시하지 않는다.

# 12. 일반 장애물

현재 기본 장애물은 3종이다.

## 12.1 바위

- 1개의 레인 차지
- 가장 기본적인 장애물
- 상/중/하 모든 레인 등장 가능
- 화면 오른쪽에서 왼쪽으로 이동

## 12.2 상어

- 2개의 인접한 레인 차지
- 가능한 위치:
  - 상단 + 중단
  - 중단 + 하단
- 바위보다 큰 이동형 장애물

## 12.3 고래

- 2개의 인접한 레인 차지
- 가능한 위치:
  - 상단 + 중단
  - 중단 + 하단
- 상어보다 크고 화면을 오래 차지하는 장애물로 표현 가능

현재는 이 3종만 우선 구현한다.

통나무, 수초, 낚싯바늘, 어망 등의 추가 일반 장애물은 **후순위**다.

---

# 13. 일반 장애물 패턴

완전 랜덤 생성보다는 미리 검증된 패턴을 랜덤 호출한다.

기본 패턴 예시:

1. 바위 1개
2. 서로 다른 두 레인에 바위 2개
3. 시간차를 둔 연속 바위
4. 상어 — 상+중
5. 상어 — 중+하
6. 고래 — 상+중
7. 고래 — 중+하
8. 상어 + 바위로 3레인 차단 → 점프 필수
9. 고래 + 바위로 3레인 차단 → 점프 필수

모든 패턴은 반드시 최소 1개의 회피 방법이 존재해야 한다.

---

# 14. 일반 구간 점프 필수 패턴 규칙

일반 게임에서 플레이어가 물속 이동만 반복하지 못하도록 점프 필수 패턴을 사용한다.

예시:

- 상단+중단: 상어
- 하단: 바위
- 물속 3레인 모두 차단
- 해결법: 상단 이동 후 점프

또는

- 상단: 바위
- 중단+하단: 고래
- 해결법: 상단 이동 후 점프

## 안전 규칙

- 점프 쿨타임 중에는 점프 필수 패턴 생성 금지.
- 점프 필수 패턴 직후 바로 다음 점프 필수 패턴 생성 금지.
- 점프 필수 패턴 사이 최소 약 2초 이상 여유.
- 플레이어가 하단에 있어도 상단까지 이동 후 점프할 반응 시간을 보장.
- 절대 회피 불가능한 패턴 생성 금지.

프로토타입 기본값:

```js
MIN_JUMP_PATTERN_GAP = 2.0
```

일반 패턴 : 점프 필수 패턴 권장 비율:

- 일반 약 75%
- 점프 필수 약 25%

# 15. 일반 게임 난이도

연어 자체의 조작 속도는 게임 내내 고정한다.

난이도는 다음 두 가지로만 높인다.

1. 장애물 이동 속도 증가
2. 장애물 등장 빈도 증가

플레이어 조작을 느리게 하거나 무겁게 만들어 난이도를 올리지 않는다.

구간이 뒤로 갈수록 난이도를 상승시킨다.

- 게임 진행 1: 쉬움
- 게임 진행 2: 보통
- 게임 진행 3: 어려움
- 게임 진행 4: 엔딩 직전 구간이므로 오히려 장애물을 줄이고 잔잔하게 마무리

---

# 16. 공통 충돌 / 실패 규칙

- 기본적으로 장애물에 **한 번 충돌하면 실패**.
- 체력 시스템 없음.
- 목숨 시스템 없음.
- 회복 아이템 없음.
- 충돌 후 무적시간 없음.

충돌 연출은 짧게:

1. 약 0.1초 순간 정지
2. 작은 충돌 효과
3. 연어가 살짝 밀리거나 흔들림
4. 실패 처리

---

# 17. 체크포인트 / 재시작

스토리형 완주 게임이므로 체크포인트를 사용한다.

- 일반 구간에서 실패 → 해당 일반 구간 시작부터 재시작
- 보스에서 실패 → 해당 보스 시작부터 재시작
- 이미 본 중간 컷신은 보스 재도전 시 자동 스킵 가능

이전 보스나 이전 일반 구간을 반복하게 하지 않는다.

---

# 18. 보스전 공통 시스템

세 보스 모두 **동일한 기본 형식**을 사용한다.

## 공통 규칙

- 모든 보스전 시간: **30초**
- 화면에 30초 카운트다운 표시
- 공격 전에 반드시 **공격 히트박스 / 위험 레인 예고 표시**
- 플레이어는 예고된 영역을 보고 ↑ / ↓ / 점프로 피한다.
- 보스에게 공격하거나 HP를 깎는 시스템 없음.
- 30초 동안 버티면 보스 클리어.
- 한 번 맞으면 보스전 실패.
- 실패 시 해당 보스 시작부터 재도전.
- 새로운 공격 버튼은 추가하지 않는다.

공통 구조:

> 히트박스 예고 → 실제 공격 → 공격 종료 → 다음 히트박스 예고 → 반복 → 30초 종료 → 클리어

프로토타입용 공통 임시값 예시:

```js
BOSS_DURATION = 30
BOSS_TELEGRAPH_DURATION = 0.8
BOSS_ATTACK_DURATION = 0.7
BOSS_RECOVERY_DURATION = 0.5
```

위 수치는 모두 CONFIG에서 수정 가능하게 한다.

# 20. 보스 1 — 낚싯줄

## 핵심 개념

> **3개의 레인 중 공격이 예고된 1개 레인을 피한다.**

보스전 시간: **30초**

공격 전에 반드시 해당 레인 전체에 빨간 히트박스/위험 영역을 먼저 표시한다.

잠시 후 해당 레인으로 낚싯줄과 낚싯바늘이 내려온다.

플레이어가 해당 레인을 피했다면 낚싯줄은 그대로 지나가고 다음 공격 예고가 시작된다.

이 과정을 30초 동안 반복한다.

## 공격 패턴 — 총 3개

### 패턴 1

- 상단 레인 위험 표시
- 상단 레인에 낚싯줄/바늘 등장
- 중단 또는 하단으로 회피

### 패턴 2

- 중단 레인 위험 표시
- 중단 레인에 낚싯줄/바늘 등장
- 상단 또는 하단으로 회피

### 패턴 3

- 하단 레인 위험 표시
- 하단 레인에 낚싯줄/바늘 등장
- 상단 또는 중단으로 회피

## 보스 특징

- 1보스이므로 가장 단순하다.
- 매 공격마다 위험한 레인은 1개뿐이다.
- 상/중/하 세 패턴을 랜덤하게 반복한다.
- 같은 패턴이 여러 번 연속될 수 있는지는 CONFIG에서 쉽게 조정 가능하게 한다.

한 줄 요약:

> **“표시된 한 줄을 피하면서 30초 버틴다.”**

# 22. 보스 2 — 바다코끼리

## 기본 상황

연어와 바다코끼리는 모두 같은 진행 방향인 **오른쪽으로 이동 중**이다.

바다코끼리가 뒤에서 쫓아오는 별도 추격게임으로 만들지 않는다.

화면상 바다코끼리는 플레이어보다 오른쪽 또는 공격이 잘 보이는 위치에 배치하고, 정해진 공격 애니메이션을 사용한다.

공격 전에 반드시 해당 레인에 빨간 히트박스/위험 영역을 보여준다.

보스전 시간: **30초**

## 최신 보스 2 공격 패턴

현재 최신 전달 내용을 기준으로 바다코끼리의 공격 범위는 다음과 같이 구성한다.

### 단일 레인 공격 — 입 벌리고 돌진

#### 패턴 1

- 상단 레인 히트박스 표시
- 바다코끼리가 입을 벌리고 상단 레인으로 돌진

#### 패턴 2

- 중단 레인 히트박스 표시
- 바다코끼리가 입을 벌리고 중단 레인으로 돌진

#### 패턴 3

- 하단 레인 히트박스 표시
- 바다코끼리가 입을 벌리고 하단 레인으로 돌진

### 2레인 공격 — 팔과 입을 벌리고 돌진

#### 패턴 4

- 상단 + 중단 히트박스 표시
- 바다코끼리가 팔과 입을 벌리고 상단+중단을 차지하며 돌진
- 플레이어는 하단으로 회피

#### 패턴 5

- 중단 + 하단 히트박스 표시
- 바다코끼리가 팔과 입을 벌리고 중단+하단을 차지하며 돌진
- 플레이어는 상단으로 회피

## 보스 특징

- 낚싯줄보다 공격 범위가 넓고 직접적인 위협이다.
- 입만 벌린 돌진과 팔까지 벌린 큰 돌진을 시각적으로 명확하게 구분한다.
- 공격 전 빨간 히트박스를 반드시 먼저 보여준다.
- 30초 동안 공격을 피하면 클리어.

한 줄 요약:

> **“바다코끼리의 공격 범위를 미리 보고 30초 동안 피한다.”**

# 24. 보스 3 — 폭포

## 핵심 개념

> **강한 급류와 돌이 지나가는 위험 레인을 보고 30초 동안 피한 뒤, 마지막에 점프로 폭포를 넘는다.**

보스전 시간: **30초**

모든 공격 전에 반드시 해당 레인의 빨간 히트박스/위험 영역을 먼저 표시한다.

히트박스 표시 후 해당 레인으로 **강한 급류 + 기존 일반 장애물인 돌**이 빠르게 지나간다.

## 공격 패턴 — 총 6개

### 패턴 1

- 상단 레인 공격

### 패턴 2

- 중단 레인 공격

### 패턴 3

- 하단 레인 공격

### 패턴 4

- 상단 + 중단 공격
- 플레이어는 하단으로 회피

### 패턴 5

- 중단 + 하단 공격
- 플레이어는 상단으로 회피

### 패턴 6

- 상단 + 중단 + 하단 전체 공격
- 물속 3개 레인 모두 위험
- 플레이어는 상단으로 이동 후 **점프**해서 회피

## 30초 종료 시

30초를 버티면 마지막 거대한 폭포 돌파 연출을 실행한다.

- 연어가 상단 레인으로 이동할 수 있는 짧은 안전 구간 제공
- 점프 가능 상태 보장
- 플레이어가 상단에서 ↑ 입력
- 연어가 크게 점프
- 폭포 돌파
- 보스 3 클리어

한 줄 요약:

> **“급류와 돌을 30초 피한 뒤 마지막 점프로 폭포를 넘는다.”**

# 27. 엔딩 스토리

연어가 자신이 어린 시절 살던 자갈밭에 도착한다.

과거의 어린 연어 모습이 잠깐 겹친다.

과거:

> “나중에 다시 돌아오게.”

현재의 연어:

> “진짜…”
>
> “돌아왔네.”

게임 내내 사용했던 “그래도 가야지.”는 엔딩에서 사용하지 않는다.

더 이상 가야 할 곳이 없기 때문이다.

자갈 사이에 새로운 생명이 이어질 것을 짧게 암시한다.

마지막 문구:

> **“처음 품은 뜻을, 끝까지.”**
>
> **初志一貫**

권장 엔딩 길이: 약 10~20초.

# 31. 아트 방향

- 단순한 형태
- 명확한 실루엣
- 물속 배경은 청록/파랑 계열
- 플레이어 연어는 주황/붉은 계열로 배경과 확실히 구분
- 위험 히트박스는 반투명 빨간색
- 안전 공간은 별도 과도한 색 강조 없이도 인식 가능하게 구성
- 바위, 상어, 고래, 보스의 형태를 한눈에 구분 가능하게 제작

캐릭터 표정 최소 종류:

- 기본
- 긴장
- 겁먹음
- 지침
- 결심
- 엔딩의 안도/기쁨

# 35. Claude 구현용 코드 구조 권장

주요 밸런스 값은 한 곳에서 수정 가능하게 한다.

예시:

```js
const CONFIG = {
  lanePositions: [250, 360, 470],
  laneMoveDuration: 0.2,
  jumpDuration: 0.8,
  jumpCooldown: 1.2,

  bossDuration: 30,
  bossTelegraphDuration: 0.8,
  bossAttackDuration: 0.7,
  bossRecoveryDuration: 0.5,

  minJumpPatternGap: 2.0,
  jumpPatternChance: 0.25,

  // 일반 구간 장애물 속도/생성 간격은 구간별로 별도 설정
};
```

스토리 데이터도 코드와 분리한다.

```js
const STORY_DATA = {
  intro: [...],
  cutscene1: [...],
  cutscene2: [...],
  cutscene3: [...],
  ending: [...]
};
```

보스 패턴도 데이터화한다.

```js
const BOSS_PATTERNS = {
  fishingLine: [...],
  walrus: [...],
  waterfall: [...]
};
```

새로운 장애물이나 패턴을 추가할 때 전체 코드를 수정하지 않아도 되는 구조로 만든다.

# 36. 절대 지켜야 할 구현 규칙

1. 게임은 사이드뷰다.
2. 기본 레인은 3개다.
3. 플레이어는 좌우로 움직이지 않는다.
4. 모든 보스전은 30초다.
5. 모든 보스 공격 전에 반드시 히트박스/위험 영역을 미리 보여준다.
6. 보스에게 공격하는 시스템은 만들지 않는다.
7. 보스전 조작도 일반 게임과 동일한 ↑ / ↓ / 점프만 사용한다.
8. 일반 구간과 보스 모두 한 번 충돌하면 실패한다.
9. 회피 불가능한 일반 패턴을 생성하지 않는다.
10. 점프 쿨타임 중 점프가 반드시 필요한 일반 패턴을 생성하지 않는다.
11. 보스 실패 시 해당 보스부터 재시작한다.
12. 보스 클리어 후 별도 컷신 없이 다음 일반 구간으로 연결한다.
13. 세 번째 보스 뒤에도 마지막 일반 게임 구간이 존재한다.
14. 마지막 목적지에 도착해야 엔딩이 나온다.
15. 새 시스템을 임의로 추가해 게임을 복잡하게 만들지 않는다.

# 38. Claude에게 최종 요청

이 문서를 설명만 하지 말고, 이 기획을 기준으로 **실제로 플레이 가능한 게임 프로토타입을 바로 구현한다.**

가능하면:

- HTML/CSS/JavaScript
- 별도 설치 없이 실행
- 하나의 HTML 파일 또는 최소 파일 구성
- 외부 유료 에셋 필요 없음
- 임시 도형/간단한 SVG/Canvas 그래픽 사용 가능

으로 제작한다.

그래픽 완성도보다 우선해야 할 것은:

1. 조작감
2. 회피 가능 여부
3. 보스 공격 가독성
4. 30초 보스 루프
5. 컷신→보스 연결
6. 처음부터 엔딩까지 게임 흐름 완성

이다.

확정되지 않은 미세한 수치는 질문하지 말고 합리적인 프로토타입 값을 적용한다.

단, 임시값은 반드시 CONFIG에서 쉽게 변경할 수 있게 한다.

# 39. 현재 후순위 / 아직 확정할 필요 없는 사항

게임 완성 전에는 아래 사항에 시간을 쓰지 않는다.

- 주인공 이름
- 추가 캐릭터
- 복잡한 세계관
- 추가 일반 장애물
- 캐릭터 스킨
- 상점
- 코인
- 강화
- 스킬
- 아이템
- NICE 판정
- 콤보
- 근접 회피 보너스
- 긴 컷신
- 과도한 배경 종류
- 과도한 애니메이션

현재 목표는 **짧지만 처음부터 엔딩까지 완성되어 있고, 보스 3종이 확실히 구분되는 플레이 가능한 게임**이다.
